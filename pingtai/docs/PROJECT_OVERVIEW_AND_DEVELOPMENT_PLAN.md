# 工业自动化测试平台 - 项目概览与开发计划

## 📊 项目整体架构

### 核心定位
这是一个**工业自动化测试平台**（Industrial Automation Platform），采用严格的DDD架构设计，支持多种工业测试场景：
- 编码器测试
- AOI检测  
- ATS测试
- 工业老化测试
- 工装测试
- 单产线MES

### 技术栈
**前端：**
- Vue 3.4 + TypeScript + Vite
- Element Plus UI组件库
- Pinia状态管理
- FastCRUD快速开发框架

**后端：**
- Django 4.2 + Django REST Framework
- Python 3.11+
- MySQL 8.0数据库
- Redis缓存
- Celery异步任务

**架构：**
- DDD领域驱动设计
- Actor并发模型
- EventBus事件驱动
- CQRS读写分离

### 项目结构
```
django-vue3-admin/
├── backend/                    # 后端代码（纯代码，无文档/日志）
│   ├── platform/              # 工业平台内核（永久稳定）
│   │   ├── runtime/           # Runtime、EventBus、Actor、Snapshot
│   │   ├── domain/            # DDD领域模型（通用抽象）
│   │   ├── storage/           # CQRS存储、Repository
│   │   ├── application/       # 通用应用服务
│   │   ├── api/               # 平台API
│   │   └── codegen/           # 代码生成引擎
│   ├── projects/              # 所有工业项目
│   │   └── encoder_test/      # 编码器测试项目
│   │       ├── actions/       # 编码器/电机/电源动作
│   │       ├── drivers/       # 编码器/电机/电源驱动
│   │       ├── testcases/     # 编码器测试用例
│   │       ├── flows/         # 编码器测试流程
│   │       ├── configs/       # 编码器测试配置
│   │       └── adapters/      # 平台适配层
│   ├── shared/                # 通用工具
│   │   ├── drivers/           # 可复用的驱动
│   │   ├── utils/             # 工具函数
│   │   └── logging/           # 日志系统
│   ├── dvadmin/               # Django Admin系统
│   ├── application/           # Django应用配置
│   └── conf/                  # 配置文件
├── web/                       # 前端代码
├── docs/                      # 统一文档目录
│   ├── backend/               # 后端文档
│   └── drivers/               # 设备文档
└── logs/                      # 统一日志目录
```

## 🎯 当前项目状态

### ✅ 已完成模块

#### 1. 平台内核层
- **Runtime系统**：Actor模型、EventBus、Mailbox、Snapshot、Recovery
- **Domain层**：聚合根、状态机、设备/任务/工位/告警/报告抽象
- **Storage层**：Repository模式、MySQL持久化
- **CodeGen系统**：设备代码自动生成、模板引擎

#### 2. 共享工具层
- **通信驱动**：RS485、TCP、CAN、USB、VISA
- **协议支持**：Modbus RTU、SCPI、自定义ASCII
- **基础设备**：BaseDevice、BaseComm、BaseProtocol

#### 3. 编码器测试项目
- **设备驱动**：编码器、电机、激光、功率放大器
- **测试引擎**：测试用例管理、任务调度、数据采集
- **业务流程**：启动流程、校准流程
- **适配器层**：设备/任务/工位适配器

#### 4. 管理系统
- **用户权限**：RBAC权限控制、菜单管理、角色管理
- **系统管理**：字典管理、文件管理、操作日志
- **测试管理**：测试用例CRUD、测试任务管理

## 📝 开发规范提醒

### 架构约束
- ✅ Platform层保持通用稳定
- ✅ Projects层实现业务逻辑
- ✅ Shared层提供可复用能力
- ❌ 禁止修改Platform内核
- ❌ 禁止跨层依赖

### 代码规范
- ✅ 遵循三阶段生命周期（Construct → Initialize → Start）
- ✅ 使用延迟初始化函数（get_xxx()）
- ❌ 禁止import副作用
- ❌ 禁止在ready()中执行IO操作

### 数据库规范
- ✅ 使用MySQL 8.0 + InnoDB
- ✅ 字符集utf8mb4_unicode_ci
- ✅ 包含工业时间维度字段
- ❌ 禁止CASCADE DELETE
- ❌ 禁止复杂触发器

### 命名规范
- ✅ 遵循工业平台命名规范
- ✅ 使用清晰的业务术语
- ❌ 禁止缩写和模糊命名
- ❌ 禁止中英文混用

1. **设备联调**：确保与真实设备的稳定通信
2. **异常恢复**：构建可靠的异常处理机制  
3. **稳定性优化**：提升系统在工业环境下的可靠性
4. **功能完善**：补充测试引擎、设备管理、工单系统等功能

建议按照P0 → P1 → P2 → P3的优先级逐步推进，确保每个阶段都有可交付的成果。
